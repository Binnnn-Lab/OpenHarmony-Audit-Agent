使用场景 依赖与配置 网络要求

03安装与命令操作

以下命令在仓库根目录执行，示例使用 Windows PowerShell。运行时采用独立虚拟环境，命令直接指定解释器，无需修改 PowerShell 执行策略。

1. 安装基础工具

python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m openharmony_audit --help

帮助信息应列出 validate-target、prepare、normalize-sarif 和 report。Linux / macOS 使用 .venv/bin/python 替换上述解释器路径。

2. 加载抽象目标配置

.\.venv\Scripts\python.exe -m openharmony_audit validate-target --target config/target.openharmony.abstract.json

终端输出目标快照、分析单元和威胁模型的 JSON。该命令加载目标配置并构造模型，当前不执行完整 JSON Schema 校验。

3. 生成任务计划

.\.venv\Scripts\python.exe -m openharmony_audit prepare --target config/target.openharmony.abstract.json --run-root reports/run-data --workers 2

检查 reports/run-data/plan.json 和 workers/worker-*/assignment.json。candidates、evidence、reports 目录用于后续产物。worker 数按分析单元数量限制；重复使用相同目录会更新计划文件。

4. 导入已有 SARIF（可选）

.\.venv\Scripts\python.exe -m openharmony_audit normalize-sarif --sarif path/to/results.sarif --output reports/run-data/findings.json

将 path/to/results.sarif 替换为自己的 SARIF 文件路径。终端显示归一化数量，输出 JSON 可查看规则、位置与路径字段。本操作不执行 CodeQL 扫描，也不判定漏洞是否成立。

5. 生成技术方案报告（可选）

.\.venv\Scripts\python.exe -m pip install -e ".[pdf]"
.\.venv\Scripts\python.exe -m openharmony_audit report --output reports/technical-report.md --pdf reports/technical-report.pdf

命令生成技术方案 Markdown 和 PDF，并覆盖同名输出文件。当前报告入口不读取上述 findings.json；实际漏洞报告的自动汇总仍需接入。

6. 扩展引擎配置

需要 CodeQL-AI 模块时安装 python -m pip install -e ".[codeql-ai]"（使用同一虚拟环境）。模型配置只记录模型名、端点和环境变量名，密钥由进程环境提供。示例配置需要替换占位值；当前基础 CLI 不会自动读取该配置并启动模型。

04HTML DEMO 操作

双击 frontend/demo.html 可离线演示。附录使用说明书和旧工作台依赖同目录文件，分享完整材料时保留 frontend 目录结构。 

python scripts/serve_demo.py
# 浏览器访问：http://127.0.0.1:8765/demo.html
# 使用说明书：http://127.0.0.1:8765/manual.html
# 结束服务：Ctrl+C
  1. 点击“开始演示”，第二章点击架构节点查看两个工具的分工。
  2. 第三章点击“展开下一步”，查看五个步骤中的代码高亮、候选记录和证据说明。
  3. 第四章设 n=96、容量 64，观察危险条件。把 n 改成 32，观察当前输入安全与输入域中仍存在危险值的区别。打开容量检查，观察路径条件冲突。
  4. 第五章点击四种结论，查看各自需要的证据；第六章点击经验记录、回归和复用节点。
  5. 第七章介绍对照实验方案，第八章汇总，并提供使用说明书和旧工作台入口。

快捷键：← / →、PageUp / PageDown 推进；N 显示讲解提示；F 全屏；Escape 收起提示并暂停播放。第三章包含五个子步骤。底部数字跳转章节；自动播放每 9 秒推进，手动操作或切换标签页会暂停。

约束实验在浏览器枚举 0…256 的整数，容量固定为 64。它展示简化条件下的计算结果，未调用 SMT、执行内存复制或运行真实 PoC。完整保护、无整数溢出等假设会影响结论的适用范围。

05常见问题与检查

现象 处理方法
本地地址打不开 保持服务终端运行；端口占用时使用 python scripts/serve_demo.py --port 8766，并访问对应端口。也可直接打开 HTML 文件。
No module named openharmony_audit 确认在仓库根目录安装，安装和运行使用同一虚拟环境解释器。
配置或 SARIF 文件不存在 检查当前目录和 --target / --sarif 路径，带空格的路径用引号包裹。
PDF 依赖或字体错误 安装 .[pdf] 并确认默认字体存在。字体路径可由 build_pdf 的 font_path 参数指定；CLI 暂未暴露此选项。
模型端点或认证失败 确认占位端点已替换、模型可用、密钥环境变量对当前进程生效；HTML 演示无需模型配置。
预期看到真实扫描结果 当前网页展示预置案例，prepare 只准备计划。实际扫描、适配器调用及产物回写需要继续集成。

开发者可在 frontend 目录运行 npm ci、npm run test:demo。新版检查覆盖离线加载、案例步骤、约束边界、键盘和响应式布局。旧工作台检查使用 npm test，需要启动本地服务。
